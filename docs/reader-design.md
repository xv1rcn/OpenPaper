# 阅读工作区设计决策

日期：2026-11-23。状态：研究与设计方案，尚未实现。本方案接替 reading-layout.md 中的局部排版方向；上一轮实现保留作过渡，不表示方案已验收。

## 结论

OpenPaper 的速读应是一份有来源的论文解读文档。默认以连续正文支持理解，以章节导航支持跳读，以原文定位支持验证。书库使用卡片；正文使用标题、段落、列表、比较表、图注和引用。不会把所有内容重新做成卡片、聊天气泡或折叠面板。

研究依据是现有实现、用户截图、产品官方文档及交互研究文章；未对竞品做实机可用性测试。下列尺寸和验收时限属于本项目设计目标，不是外部研究结论。

## 当前问题的来源

1. ReaderWorkspace.vue 将 11 个模型字段直接映射成同级章节，方法概述、步骤、技术总览、模块容易重复。主要贡献出现于实验之后，问题、方法、结果的主线被打断。
2. StructuredRead 仍是递归字段展示器。固定字段顺序只能让数据更整齐，不能表达实验比较、证据与结论的关系。
3. TechnicalRead 将 role、mechanism、technical_explanation 连成段落；没有可靠来源标记时，读者可能把补充背景当成论文描述。精确去重也不能解决语义重复。
4. 默认 50/50 双栏加多层工具栏，使 1024×768 默认窗口正文空间不足。全局页码与 PDF 自有页码重复，重新生成、删除等低频操作常驻。
5. 字号、标题、缩进、边框以前跟数据嵌套层级绑定，信息重要程度反而不清楚。
6. 上次采用一页合成测试文档，只能验证流程，无法证明长篇论文的阅读体验。

## 调研如何影响决策

| 依据 | 可以借鉴的机制 | OpenPaper 的选择 |
|---|---|---|
| Readest Customization | 阅读字号、行距、最大宽度和 CJK 排版可调 | 独立正文排版参数；不靠增加卡片间距改善可读性 |
| Readest Parallel Read | 独立面板和阅读位置；窄屏需要处理空间竞争；长度不一致时手动滚动更合适 | 原文和解读独立滚动；页码引用驱动定位，不做默认比例同步 |
| Zotero PDF Reader and Note Editor | 笔记中的引用可以回到原文页 | 把“读结论→查来源→回到解读”作为首要交互 |
| Readwise PDF 文档 | 原始 PDF 与可重排文本是不同阅读视图 | 明确区分原文与解读的职责，不把 PDF 缩得很小来给全部工具腾位置 |
| NN/g Progressive Disclosure | 常用能力前置，低频或高级能力按需展开 | 收起生成参数、导出格式、术语补充；不隐藏核心机制和关键限制 |

## 页面结构与模式

顶部单行：返回书库、论文标题、视图切换（解读 / 对照 / 原文）、阅读设置、更多。初始目标高度 48–56 CSS px；不含操作系统标题栏。已有结果时“重新生成、导出、刷新、删除”进入更多菜单，导出再选择格式。无结果时主区域显示生成入口；进行中显示就地状态，失败保留可重试入口。

默认解读模式，正文居中，不先占一半宽度放 PDF。保留已保存用户的视图和阅读位置。对照模式保留原文在左、解读在右，分隔线拖动调整比例；各面板独立滚动。原文模式只显示 PDF。切换模式不卸载已有结果、不丢位置。

章节导航为一条紧凑的当前章节/目录入口。宽屏可选固定侧目录；1024 窗口不默认再占第三栏。目录是锚点导航，不是将章节互相隐藏的页签。当前章节随解读滚动更新，点击引用不改变解读位置。

双栏可用宽度低于两侧最低宽度之和（初始每侧约 360 px，不含边距）时，使用单面板切换。宽度阈值按实测调整；不得通过缩小字号维持双栏。缩窄窗口时保存原模式，恢复宽度后允许返回。

PDF 页码、缩放和搜索只在 PDF 面板中出现一次；搜索框按需展开。宽度滑块移除，分隔线支持鼠标和键盘调整。正文与 PDF 内部滚动，标题栏与工具栏不随正文滚动。

## 信息架构

| 章节 | 读者问题 | 现有字段及组织方式 |
|---|---|---|
| 概览 | 研究什么、有什么发现？ | one_sentence 作导语；quick_takeaways 作短列表；problem_and_motivation 作背景；contributions 保留为贡献说明，避免与要点重复铺陈 |
| 方法 | 怎么做到的？ | method_overview 作路线说明；method_steps 仅对真实步骤编号；technical_detail_read.modules 作具名小节；技术 summary 只在补充独有信息时进入主线 |
| 实验与证据 | 如何支持结论，适用范围是什么？ | summary 引入；main_results 先给结论和证据；compared_methods、datasets、metrics 按比较、设置、指标分别呈现 |
| 局限与复现 | 哪些不能推出，能否复现？ | limitations、方法/实验 missing_details、evaluation_design_notes、reproduction_notes、difficulty、workload 分组；重要局限在相关结果附近也保留 |
| 图表与精读 | 哪些原文值得继续看？ | figure_insights 用图+图注；deep_read_suggestions 列表。没有可靠关联时保持独立，不猜测把图插入方法或实验 |

不使用前端语义去重、模糊匹配或自动摘要悄悄丢弃旧数据。旧缓存中的重叠描述暂放本章节的“补充说明”，内容完整保留且可展开；主要内容的归属通过显式字段映射确定。新生成内容通过明确字段职责减少重复。完全相同的内容可去重，必须保留引用的并集。

## 方法正文规则

每个模块：具体名称作为三级标题，作用用一句引导，工作机制为正文，必要的背景解释作为明确标注的补充。不要显示“名称”“作用”“technical_explanation”等字段标签。不要强行给没有顺序关系的模块编号，不把对照方法和本文方法暗示成流水线。

章节、小节、正文最多三层视觉层级；段落不因嵌套变小。正文不加背景色，不包围边框。仅引用原句使用短引文样式；算法、公式、真正的对比关系使用适合的表示。

术语首次相关位置提供可点击的解释入口，键盘可访问，点击后显示短释义及“论文语境/通用背景”来源类别。长解释就地展开，避免在小浮层中再次滚动。所有术语仍能在章节末尾展开查看。旧数据没有可靠的来源字段时，标为“补充解释”，不推断为论文证据。

## 实验正文规则

先呈现主要发现，再呈现实验条件。默认每项发现为“结论段落 + 证据段落 + 引用”，避免每项都成为同样外观的卡片。

比较表仅用于真正可对齐的信息，初始不超过 3–4 列。旧 compared_methods 可展示“方法 / 角色 / 报告结果”；缺少结果的单元格用短缺失标记，不编造数字。数据集设置与指标解释可用紧凑定义列表，不为了统一样式塞入表格。

数值表必须有指标名、单位、方向及条件。现有 schema 没有结构化数值时保留原文结果，禁止前端从自然语言猜测抽取成排行。窄面板用标有列名的连续记录替代表格，而不是隐藏列或产生整页横向滚动。

## 原文与证据

页码是轻量引用链接，例如“原文 p.4”，位于所支持的段落或模块末尾。点击打开/切换原文并定位页码，保留解读锚点；显示“返回解读”入口。现阶段只有页码，只承诺定位到页；没有文本定位依据时不能伪造精确高亮。

论文陈述、通用背景、模型分析需要区分，但不在每段挂一串彩色标签。背景与分析使用简短旁注；未经验证的旧解释不升级为“论文原文”。全文结果区域有一个低干扰的 AI 解读标识，生成模型和时间移入更多菜单，不在各段重复免责声明。

## 排版初值

- 正文默认 16 px，行高约 1.8，可调字号；段后 10–14 px。标题 22 / 17–18 px；引用和辅助说明 12–13 px。
- 单栏正文目标每行约 32–44 个汉字、最大宽度约 720 px；双栏以可用宽度为准，不为满足字数牺牲字号。
- 章节间距 32–40 px，小节间距 20–24 px；层级依靠字重和留白，避免每段都用分隔线。
- 浅色正文用接近白色的阅读背景、深灰文字；深色使用对应语义色。绿色仅用于可操作链接、当前导航和少量状态，不作为整块正文底色。
- 表格、图片限制在面板内；长公式/代码块允许局部滚动；中文、长英文术语和引用链接均测试换行。

## 实现边界和顺序

1. 为现有结果建立显式阅读模型，将字段映射到章节、段落、模块、对比、图注、术语和引用；保留原始缓存。普通章节不再依赖通用递归 StructuredRead。
2. 先实现方法与实验的专用正文组件，使用长短不同的真实论文缓存做视觉原型；对照当前版本检查信息保留。
3. 改工作区单行工具栏、视图模式、目录与引用回跳；验证默认 1024×768 的实际可用空间。
4. 再调整生成 schema/prompt，明确 overview、mechanism、background、claim/evidence 的职责；版本化兼容旧缓存。读缓存不能触发重生成或额外费用。缺乏证据时不强行填满字段。
5. 最后对齐 PDF/PPTX 导出顺序和证据表示，避免屏幕与导出内容组织不一致。

不需要引入 LangChain，不需要重写 Python 后端。先实现 frontend/src/lib/reading-document.ts 的纯映射及方法、实验、引用、术语组件；后续 schema 更新局限于生成、归一化和导出相关模块。

## 验收而非只做截图

至少选择三类样本：短方法论文、含多组实验与表格的长论文、以论证/综述为主而非标准实验的论文。合成 fixture 继续负责自动化，但不独自承担视觉验收。无需使用真实 API Key 重新生成即可先检查现有缓存。

任务目标：进入后 10 秒内找到研究问题与主要发现；从方法模块两次以内操作到达对应原文页；返回后保留解读位置；不展开术语也能理解主线；关键局限不会被默认折叠。时间是设计验收目标，必须实测，不能声称已达成。

尺寸：1024×768、1280×800、1440×900；窄窗和放大字号；浅色/深色；鼠标和键盘。检查：工具栏不滚走、正文无嵌套卡片、无整页横向滚动、表格不丢列、缩放模式切换不丢位置、术语可关闭并恢复焦点。

数据回归：历史字符串和多版本缓存、空/缺字段、未知字段、多个来源页、0/false、无实验论文。原始信息不能因视图映射丢失，必要时保留补充区；未知字段不直接占据主要阅读区。
